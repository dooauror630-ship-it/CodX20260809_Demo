# 综合农牧业管理系统完整测试流程与核心功能验收

本文用于测试环境部署验收、版本回归和正式发布前放行。测试过程中的所有写入操作必须使用名称以 `_test` 结尾的数据库；正式数据库只允许执行发布后的只读检查。

## 1. 测试目标

验证以下闭环可以稳定完成，并且页面、API、数据库流水、库存/存栏余额和经营分析结果一致：

`账号与权限 → 农场资料 → 采购入库 → 生产消耗 → 养殖/种植 → 采收或出栏 → 销售过账 → 收款/退货 → 利润分析`

同时验证：

- 数据库迁移可从正式当前版本升级到目标版本，并可恢复。
- 管理员、负责人、操作员、查看员的权限边界正确。
- CSRF、会话、上传附件、敏感配置和智能体读写边界有效。
- 桌面与手机页面无脚本错误、横向溢出和关键控件遮挡。
- 并发过账、幂等请求、负库存、超量退货和跨农场访问不会破坏数据。

## 2. 测试环境与隔离

### 2.1 环境要求

- 后端：Python、Flask、Waitress。
- 前端：Node.js、npm、Vue 3、Vite。
- 数据库：MySQL 测试库 `agriculture_management_test`；SQLite 仅用于快速单元测试。
- 浏览器：桌面 Chromium/Chrome 和移动模拟设备（建议 Pixel 7 视口）。
- 测试服务与正式服务使用不同端口、进程、配置、数据库账号和附件目录。

### 2.2 测试账号与数据

准备至少 2 个农场和以下账号：

| 账号 | 角色 | 用途 |
|---|---|---|
| admin | 管理员 | 用户、全局分析、基础资料维护 |
| manager-a | 负责人 | 农场内完整经营操作 |
| operator-a | 操作员 | 业务录入和过账 |
| viewer-a | 查看员 | 只读、越权验证 |

每个农场准备：仓库、物料分类、饲料/兽药/种子/肥料/农药/产品、供应商、客户、猪批次、肉鸡批次、种植地块和至少一种作物周期。库存要覆盖正常、零库存、低库存、临期和批号场景。

## 3. 执行顺序

### 3.1 获取版本与工作区检查

1. 记录 Git 分支、提交号、构建时间和目标迁移版本。
2. 确认工作区无未提交的业务代码变更。
3. 确认测试配置未包含正式数据库密码、正式 Session 密钥或真实附件。
4. 确认测试数据库名以 `_test` 结尾。

```powershell
git status --short --branch
git log -1 --oneline
$env:AGRI_MYSQL_DATABASE = "agriculture_management_test"
```

### 3.2 静态检查与快速自动化测试

```powershell
python -m ruff check .
python -m compileall -q backend
python -m pytest -q
cd frontend
npm.cmd run lint
npm.cmd run test:unit
npm.cmd run typecheck
npm.cmd run build
cd ..
```

通过标准：无 Ruff、编译、后端测试、ESLint、Vitest、TypeScript 或 Vite 构建错误。允许跳过的测试必须有明确原因并记录。

### 3.3 数据库恢复与迁移演练

1. 计算备份文件 SHA-256，并验证 GZip/SQL 可读。
2. 将备份恢复到 `agriculture_management_test`，禁止恢复到正式库。
3. 执行全量迁移或从正式当前版本执行增量迁移。
4. 运行结构校验、库存对账和销售对账。

```powershell
.\scripts\verify-backup.ps1 -BackupFile <backup.sql.gz>
.\scripts\restore-drill.ps1 -BackupFile <backup.sql.gz> -TestDatabase agriculture_management_test
.\scripts\mysql-migration-drill.ps1 -BackupFile <backup.sql.gz>
```

通过标准：迁移链无断点，目标版本为 `0025_stock_document_versions`，`schema-check`、`inventory-reconcile`、`trade-reconcile` 全部通过。

### 3.4 启动测试服务与基础健康检查

1. 启动测试 Waitress 和测试前端/Nginx。
2. 检查 `/api/health` 和 `/api/v1/system/health`。
3. 检查响应只包含服务名、数据库类型、成功状态和请求 ID，不泄露密钥或连接串。
4. 检查测试进程只监听测试端口，正式进程 PID 和端口保持不变。

```powershell
curl http://127.0.0.1:15000/api/health
curl http://127.0.0.1:15000/api/v1/system/health
```

## 4. 核心功能验收

### 4.1 认证、会话和权限

1. 首次登录、错误密码、停用账号、重复注册和密码强度校验。
2. 登录后刷新页面、记住登录、退出登录、会话过期和重新登录。
3. 登录接口先获取 CSRF Token；所有 API 写请求缺少或伪造 Token 必须返回 `403 CSRF_INVALID`。
4. 管理员可以管理用户、修改角色、停用/启用和重置密码，但不能移除自己的最后管理员权限。
5. 负责人只能访问所属农场；操作员可以执行授权业务；查看员只能读取。
6. 使用每个角色访问另一个农场的 URL、查询参数和业务单据，必须返回 403/404，不得泄露数据。
7. 验证旧 `/api/auth` 登录兼容接口和新 `/api/v1/auth` 接口行为一致。

### 4.2 农场、成员和基础资料

1. 管理员创建、修改、停用农场；农场编码重复必须被拒绝。
2. 添加、修改和移除农场成员，验证成员角色立即生效。
3. 创建仓库、物料分类、物料、供应商、客户、圈舍和地块。
4. 验证跨农场物料、仓库、圈舍、客户和地块不能互相引用。
5. 验证停用资料不能用于新采购、生产领料、销售或新业务单据。
6. 列表分页、关键词、状态筛选、空数据和无权限数据均正确。

### 4.3 采购、库存和库存分析

1. 新建采购单、修改草稿、重复单号拦截、过账入库。
2. 重复过账必须幂等，不得重复增加库存。
3. 采购退货支持部分退货，累计退货不得超过已入库数量。
4. 仓库调拨验证来源仓库存、目标仓库存和调拨流水。
5. 生产领料、退料按农场、批次或种植周期归集成本；已关闭批次禁止继续领料。
6. 盘点支持盘盈、盘亏、草稿修改、过账和取消；不得形成负库存。
7. 批号、效期、临期预警、低库存预警和库存趋势正确。
8. 并发过账同一库存时，数据库锁和错误提示正确，不得出现负库存或重复流水。
9. 逐项核对：
   `库存余额 = 所有已过账库存流水 quantity_delta 之和`。
10. 运行 `inventory-reconcile`，必须无差异。

### 4.4 生猪、肉鸡和养殖生产

1. 创建猪批次和肉鸡批次，验证物种、农场、编号和日期校验。
2. 入栏、转舍、死亡、淘汰、分批出栏和批次关闭。
3. 验证圈舍容量、数量不能为负、日期不能倒置、重复业务号幂等。
4. 登记健康/防疫/用药、称重和生产成本；已关闭批次禁止写入生产记录。
5. 核对当前存栏：入栏 - 转出 - 死亡 - 淘汰 - 出栏 = 当前存栏。
6. 核对 ADG、死亡率、估算 FCR、直接物料成本、人工/公共费用和批次成本。
7. 验证肉鸡复用养殖流程时数据不串到生猪批次。

### 4.5 种植、农事、采收和烟草烘烤

1. 创建地块和种植周期，验证面积不能超过地块可用面积。
2. 同一地块重叠周期必须拦截；周期状态只能按允许顺序流转。
3. 登记整地、播种、移栽、灌溉、施肥、用药、除草和其他农事操作。
4. 记录作业面积、人工/机械工时、人工/服务费用和多种投入品。
5. 生产领料按活动/周期归集，跨农场、跨周期、未来日期和超面积操作必须拒绝。
6. 登记分批采收，验证数量、日期和周期状态；采收后登记烟草烘烤、得率和分级。
7. 分级数量不得超过采收数量；周期关闭前必须满足必需业务条件。
8. 核对亩产、亩成本、投入成本、等级汇总和周期分析。
9. 验证大蒜、水稻、油菜模板建议、计量单位和最近周期横向对比。

### 4.6 销售、收款、退货和利润

1. 创建客户和销售单草稿，验证客户、仓库、物料、数量和价格属于同一农场。
2. 销售单过账后正确扣减库存；重复过账必须幂等。
3. 库存不足、停用物料、重复单号和非法金额必须拦截。
4. 登记收款，验证销售单、客户应收、已收金额和未收金额。
5. 登记部分/全部销售退货，库存回补，退货数量不得超过已售未退数量。
6. 验证销售详情、销售汇总、CSV 导出和按销售单利润分析。
7. 核对：
   - 销售收入 = 已过账销售明细金额。
   - 应收 = 销售收入 - 收款金额。
   - 毛利 = 销售收入 - 销售成本 - 退货影响。
   - 库存变化与销售/退货流水一致。
8. 运行 `trade-reconcile`，必须无差异。

### 4.7 综合驾驶舱、任务、审计和附件

1. 农场驾驶舱 KPI 与独立 SQL/业务记录核对：库存、存栏、作物周期、销售、收款、应收和毛利。
2. 验证趋势图、最近批次对比、空数据、加载失败、筛选和导出状态。
3. 创建任务、列表筛选、重复任务号、到期提醒和完成流转。
4. 查询审计日志，确认创建、修改、过账、退货、权限和附件动作都有记录。
5. 上传允许类型和大小范围内的附件，下载内容与上传内容一致。
6. 拒绝超大文件、危险扩展名、路径穿越、跨农场附件和未授权下载。
7. 验证附件目录不允许用户输入任意绝对路径，服务重启后文件仍可受控访问。

### 4.8 智能体只读与受控写入

1. 未配置或错误的旧 API Key 路径分别返回 `503 AGENT_API_KEY_NOT_CONFIGURED` 和 `401 AGENT_API_KEY_INVALID`。
2. 项目内置 Harness 会话只能读取允许的农场范围，验证农场列表、库存汇总、养殖汇总字段与页面及数据库一致。
3. 使用跨农场 `farmId`、负数、字符串和不存在 ID，必须拒绝或返回 404。
4. 操作员/管理员可创建采购 `DRAFT`，草稿不改变库存、成本或资金；重复相同请求返回同一草稿。
5. 只有管理员或农场负责人能使用草稿响应中的短时 `confirmationToken` 确认过账；伪造、跨用户、过期和版本冲突必须拒绝。
6. 确认过账只执行一次，库存、移动平均成本和 `CREATE_DRAFT`/`CONFIRM_WRITE` 审计记录一致；删除、批量写入和无人值守过账仍关闭。

## 6. 安全、并发和异常测试

1. SQL 注入、XSS、路径穿越、危险上传和任意文件下载。
2. 未登录访问业务 API 返回 401；普通用户访问管理员 API 返回 403。
3. 缺少 CSRF、伪造 CSRF、旧会话 Cookie 和过期会话均被拒绝。
4. 生产配置检查：MySQL、强随机密钥、关闭公开注册、启用安全 Cookie、开启 Schema 校验。
5. 并发采购过账、销售过账、退货、调拨和库存盘点，验证事务回滚和幂等。
6. 大分页、空结果、非法日期、超长文本、负数、零数量和未来日期输入。
7. 错误响应不得包含密码、连接串、堆栈、Session 密钥或服务器路径。

```powershell
.\scripts\security-scan.ps1
.\scripts\release-check.ps1
```

2. 恢复到独立 `_test` 库，验证用户、农场、库存、销售和审计数据。
3. 恢复附件目录，验证附件哈希和下载权限。
4. 恢复后执行迁移、结构检查和两项对账。
5. 记录恢复耗时、备份大小、失败点和可接受的数据丢失窗口。

## 8. 发布前与发布后门禁

### 8.1 发布前必须全部满足

- 所有自动化测试通过，跳过项有记录。
- MySQL 集成、迁移、恢复、结构和业务对账通过。
- 桌面/移动端核心 E2E 通过，截图和控制台检查无阻塞问题。
- 安全扫描、性能烟测和附件检查通过。
- 正式数据库和附件目录已有可验证备份。
- 已确认回滚命令、负责人、维护窗口和监控方式。

### 8.2 正式发布顺序

1. 停止写入或进入维护窗口。
2. 再次备份正式数据库和附件目录。
3. 使用一次性迁移账号执行 `flask db upgrade`。
4. 使用应用账号执行 `schema-check`、`inventory-reconcile`、`trade-reconcile`。
5. 重启正式服务并检查 `/api/health`。
6. 只读登录、农场列表、库存分析、销售经营和附件下载。
7. 观察错误率、响应时间、数据库连接和日志。

### 8.3 回滚条件

出现以下任一情况立即停止发布并按备份恢复，不手工修改业务表：

- 迁移失败或结构检查失败。
- 库存/销售对账出现差异。
- 登录、权限、CSRF 或核心业务接口异常。
- 数据库错误率、响应时间或连接数超过发布阈值。
- 附件不可下载、出现越权或敏感信息泄露。

## 9. 测试报告模板
